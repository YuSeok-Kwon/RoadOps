# 기상 실황·예보 이원화 감사 v0.1 / Weather Timeline Audit v0.1

작성일 / Date: 2026-11-12
최신 실행 / Latest run: 2026-11-12 20:22 KST

## 결론 / Decision

기존 파이프라인은 기상청 초단기예보의 현재와 가장 가까운 슬롯만 사용했다. W1에서는 초단기실황, 초단기예보, 단기예보를 서로 다른 원천시각으로 수집하고 제주 이벤트가 포함된 12개 기상격자에 대해 현재·1·3·6시간 총 48행의 공통 시간 테이블을 만들었다.

48행 모두 `usable`이었고 구조 품질 게이트 실패는 0건이다. 현재·1·3시간은 초단기예보, 6시간은 단기예보를 사용했다. 모든 행에는 관측시각, 예보기준시각, 예보유효시각, 수집시각을 별도로 보존했다.

## 시간 의미 / Temporal semantics

| 필드 | 의미 |
| --- | --- |
| `observed_at` | 초단기실황의 AWS 대표 관측시각 |
| `observation_fetched_at` | RoadOps가 실황 응답을 받은 시각 |
| `forecast_base_at` | 기상청이 예보를 만든 기준시각 |
| `forecast_valid_at` | 예보값이 유효한 미래 시각 |
| `forecast_fetched_at` | RoadOps가 예보 응답을 받은 시각 |
| `target_at` | RoadOps가 위험을 계산할 현재·1·3·6시간 목표시각 |

실황과 예보가 같은 강수·기온 값을 제공하더라도 같은 사실로 취급하지 않는다. 현재 행은 실황이 정상일 때 `usable`, 실황 없이 예보만 있으면 `degraded`, 둘 다 없으면 `hold`다. 미래 행은 목표시각과 60분 이내로 맞는 예보가 있을 때만 `usable`이다.

20:22 KST 실행에서 최신 실황 기준시각은 19:00 KST로 82.779분 전이었다. 기상청 발표 지연을 고려한 120분 허용선 안에 있어 현재 행에 사용했다. 현재·1·3시간 예보는 초단기예보, 다음 날 02시인 6시간 지평은 단기예보가 정확한 유효시각으로 선택됐다.

## 안전장치 / Guardrails

- 관측과 예보의 값·시각·수집시각을 별도 열로 유지
- 목표시각과 예보 유효시각의 차이를 분 단위로 기록
- 초단기예보 우선, 범위 밖이면 단기예보로 대체
- 현재 실황이 없을 때 예보로 조용히 대체하지 않고 `degraded` 표시
- 미래 예보가 없거나 60분보다 멀면 `hold`
- 격자×시간 지평 행 수와 결정적 ID 유일성 검사
- API 키와 인증 파라미터를 출력·보고서에서 제외

## 한계 / Limitations

1. 초단기실황은 5km 격자 대표 AWS 값이며 개별 도로 센서값이 아니다.
2. C-ITS 노면기상은 제공기관 관측시각이 없어 별도의 `degraded` 근거로 유지한다.
3. 48행이 모두 사용 가능하다는 결과는 API 접근성과 시간 정렬을 검증한 것이며 예보 정확도를 증명하지 않는다.
4. 기상특보는 아직 공통 시간 테이블에 연결하지 않았다.
5. 지속 수집 스케줄러와 과거 예보버전 보존은 다음 단계다.
