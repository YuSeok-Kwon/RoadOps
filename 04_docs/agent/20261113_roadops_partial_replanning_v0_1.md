# RoadOps 부분 재계획 v0.1 / Partial Replanning v0.1

작성일 / Date: 2026-11-13

## 1. 목표 / Objective

최초 배치 이후 도로통제 또는 폭우 What-if가 발생했을 때 전체 계획을 다시 섞지 않고 영향받은 팀의 남은 업무만 재계획한다. 완료 업무, 운영자 고정 업무, 영향받지 않은 팀의 방문 순서와 경로는 그대로 보존한다.

## 2. 공통 안전장치 / Guardrails

- 완료 업무는 팀별 방문 순서의 연속된 앞부분만 허용한다.
- 완료 업무의 팀·순서·사용 경로는 변경하지 않는다.
- 운영자 고정 업무는 같은 팀에 유지한다.
- 영향받지 않은 팀의 업무·순서·경로 지문은 변경하지 않는다.
- 영향팀은 이미 사용한 시간을 제외한 남은 근무시간으로만 최적화한다.
- 통제 후 경로에는 통제 링크가 포함되지 않아야 한다.
- 재계획 후 작업 중복, 필수·고정 업무, 근무시간과 경로 상태를 다시 검사한다.
- 모든 결과는 `manual_approval_required=true`이며 자동 현장 지시로 사용하지 않는다.

이번 데모에서는 동부팀 첫 업무 `link:4060438807:h0`를 완료 상태로, `link:4050418600:h0`를 동부팀 고정 업무로 두었다.

## 4. 폭우 What-if 시나리오 / Heavy-rain scenario

실제 관측을 가장하지 않기 위해 폭우는 명시적인 What-if로 주입했다. 영향 링크 `4050484600`, `4050456800`에 다음 보수 가정을 적용했다.

- 위험 우선순위 `+15점`, 최대 100점
- 현장 점검시간 `+10분`
- 영향 링크를 통과하거나 해당 현장으로 가는 이동시간 `1.25배`

## 5. 변경 설명 / Change explanation

각 시나리오 결과는 다음 정보를 함께 반환한다.

- 영향팀과 비영향팀
- 완료·고정 업무 보존 결과
- 팀별 변경 전후 업무 순서
- 변경된 경로와 팀별 이동·총소요시간 차이
- 커버리지·이동시간·최대 소요·미배정·제약 위반의 전후 차이
- `route_uses_closed_link`, `assigned_task_in_heavy_rain_area` 같은 기계 판독 사유
- 담당자가 바로 읽을 수 있는 한국어 변경 이유

각 시나리오는 `scenario_validator → preservation_planner → partial_problem_builder → affected_team_optimizer → replan_validator → change_explainer` 여섯 Tool을 거치며 모든 Tool 결과를 JSONL 감사 로그로 남긴다.

## 6. 한계 / Limitations

- 도로통제와 폭우 모두 시연용 What-if이며 실제 발생 사실을 뜻하지 않는다.
- 폭우 가중치는 운영 정책을 보여주기 위한 v0.1 값이며 과거 성능 검증을 거친 계수가 아니다.
- 비영향팀은 완전히 고정하므로 영향팀만으로 해를 찾을 수 없을 때는 전체 재계획 대신 실패한다.
- 이동시간은 제한속도 기반 자유흐름 추정치이며 실시간 ITS 혼잡과 회전제한을 반영하지 않는다.
- 현재는 최대 10개 작업 완전탐색 제약을 그대로 따른다.
- 실행시간은 현재 개발환경의 단일 측정 묶음이며 환경과 부하에 따라 달라진다.
