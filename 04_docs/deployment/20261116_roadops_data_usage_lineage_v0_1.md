# RoadOps 데이터 활용·필드 계보 명세 v0.1 / Data Usage & Field Lineage v0.1

작성일 / Date: 2026-11-16

## 1. 결론과 판정 / Decision

RoadOps의 원천 데이터부터 Agent·지도 최종 결과까지를 기계 검증 가능한 lineage로 고정했다.

- 데이터 소스: 19개
- 파생 데이터셋: 9개
- 최종 출력: Agent JSON과 웹 지도 스냅샷 2종
- 문서화된 CSV 필드·JSON leaf path: 592개
- lineage 필수 검사: 10 / 10 통과
- 원천 식별자, 변환 규칙, 코드 위치, 결측·한계 처리를 각 필드 그룹에 연결

현재 판정은 `pass_with_limitations`다. 계보 누락이 아니라, 제주데이터허브 ID 1027의 원본 재배포 조건, 항공·여객선 API 권한 차단, 미래 위험값의 시나리오 의미를 한계로 표시했기 때문이다.

기계 명세는 [`config/submission/data_lineage_v0_1.json`](../../config/submission/data_lineage_v0_1.json)이다.

## 2. 의사결정 흐름 / Decision pipeline

```text
C-ITS 이벤트·노면기상
  + 국토부 제주 표준 노드링크
  + 제주데이터허브 ID 1027 선형별 조건부 심각도
  + ITS 최신 교통
  + 기상청 실황·예보
  + TAAS 링크 구조위험
        ↓ 그레인·시각·공간결합 게이트
통합 현장 이벤트 22행 × 72열
        ↓ 4개 구성점수·결측 구간
현재 위험점수
        ↓ 기상 시간축·이벤트 지속 시나리오
0·1·3·6시간 운영 우선순위 88행 × 47열
        ↓ 동일 링크 통합·운영자 제약
현장 점검 업무
        ↓ 제주 방향성 도로망 108개 경로
안전 우선·업무 균형 배분안
        ↓ 제약 재검사·설명·수동 승인
Agent 결과·제주 도로 지도·감사 로그
```

항공·여객선 관문 데이터는 API 권한 차단으로 위 점수 흐름에 들어가지 않는다. `unavailable`을 0명·0편으로 바꾸지 않았다.

## 4. 전처리·정제 / Preprocessing and cleaning

### 그레인 보존

- C-ITS 선택 스냅샷의 원천 레코드 1건을 통합 이벤트 1행으로 유지한다.
- `event_id`는 소스·수집시각·원천순번·이벤트 ID·좌표로 만든 결정적 SHA-256다.
- 교통·날씨·TAAS·선형 선행값을 결합해도 1행을 증식하지 않는다.

### 도로 결합 등급

| 등급 | 의미 | 점수 사용 |
| --- | --- | --- |
| `exact_link_id` | 원천 링크 ID가 기준망과 정확히 일치 | 허용 |
| `spatial_fallback` | 좌표·방위·1·2순위 거리차 기준 통과 | 허용+품질 플래그 |
| `excluded` | 좌표 이상·모호한 후보 | `effective_link_id=null`, 점수·피처 결합 차단 |

`audit_matched_link_id`는 배제 행에도 감사 근거로 남을 수 있지만, 점수화에는 `effective_link_id`만 사용한다.

### 시각 정렬

- C-ITS: 제공자 발생시각 부재로 수집시각을 대리값으로 사용하고 한계 플래그를 남긴다.
- ITS: 링크별 가장 최신의 유효 관측 1건, 30분 초과 시 결측 처리한다.
- 기상: `observed_at`, `forecast_base_at`, `forecast_valid_at`, `fetched_at`, `target_at`을 분리한다.
- 미래 시간지평에 현재 ITS·C-ITS 노면관측을 복사하지 않는다.

### 결측·오류

- 결측을 0점으로 바꾸지 않는다.
- HTTP 200과 제공자 성공코드를 분리한다.
- 점수 근거 커버리지가 60% 미만이면 `hold`로 점수를 발행하지 않는다.
- 연결하지 못한 항공·여객선은 `unavailable`을 유지한다.

## 5. 피처·점수 / Features and scoring

### 필수 제주 데이터: ID 1027

| 항목 | 값 |
| --- | --- |
| 데이터명 | 제주 도로 선형별 교통사고 현황 |
| 원천 그레인 | 기준연도 × 도로선형 대·중·소분류 1행 |
| 실제 원천 | 2018~2020, 51행, SHA-256 고정 |
| 품질검사 | 복합키 중복 0, 결측 0, 음수 0, 상·하위 합계 9/9 일치 |
| 변환 | 최상위 합계만 3개 연도를 합산하여 사고 100건당 사망, 사고당 부상, 직선 대비 사망지수 계산 |
| 링크 전파 | WKT 길이/양끝 직선거리 `sinuosity`, 임계 1.02로 커브·직선 프록시 |
| 실질적 역할 | 37,087개 링크와 통합 이벤트에 결합되며 구조위험 구성점수의 30% 근거로 사용 |

이 데이터는 통행량·주행거리 분모가 없다. 따라서 링크별 사고 발생확률로 사용하지 않고, 사고가 발생했을 때의 조건부 심각도로만 사용한다.

### 설명 가능한 위험점수

| 구성 | 가중치 | 근거 |
| --- | ---: | --- |
| 현재 이벤트 | 35 | C-ITS 도로위험·공사; 노면센서행에는 미적용 |
| 구조위험 | 25 | `0.70×TAAS + 0.30×ID 1027 선형 조건부 심각도` |
| 기상·노면 | 25 | 강수·바람·시정·마찰·노면온도 중 가장 큰 신호 |
| 교통 노출 | 15 | 제한속도 대비 실제속도와 점유율 중 큰 신호 |

```text
추정점수 = 관측된 근거만의 가중합을 가용 가중치로 재정규화
하한       = 결측 근거가 모두 0점이라고 가정
상한       = 결측 근거가 모두 100점이라고 가정
근거커버리지 = 관측된 가중치 / 적용 가중치
```

점수는 사고 확률이 아니라 **도로 현장 점검 우선순위**다.

### 0·1·3·6시간 시나리오

- 현재: 최신 C-ITS·ITS·노면·기상 근거
- 미래: 해제시각이 없는 도로 이벤트 지속 시나리오 + 해당 시각 기상예보
- 미래 ITS 교통·C-ITS 노면센서·관문 유입은 예측값이 없어 결측과 상·하한으로 표현
- `forecast_semantics=operational_priority_scenario_not_accident_probability`

Agent 결과는 다음 상위 계보 그룹으로 모든 leaf path를 덮는다.

- `parsed_request`: 운영자 요청→팀·차량·시간·시점·대안 제약
- `field_tasks`: 위험예보+통합 이벤트+운영자 제약
- `allocation`: 현장업무+자원+이동시간→완전탐색

지도는 11개 `queries.*`가 각각 기준망, 위험, 업무, 팀, 경로, 지표, 재계획, 시나리오, 가용성으로 연결된다. 각 쿼리의 `source.tables`, `caveats`, `metricDefinitions.sourceLineage` 또한 웹 스냅샷에 포함된다.

## 8. 모델링·분석 의미 / Modeling semantics

- 위험점수: 학습된 사고확률이 아닌 설명 가능한 정책점수
- 1·3·6시간: 이벤트 지속+날씨 예보를 사용한 운영 시나리오
- 자원 배분: 최대 10개 업무의 결정적 완전탐색
- 안전 우선: 위험합→배정수→이동시간 순서의 사전식 목적함수
- 업무 균형: 안전안 위험합의 95% 이상에서 최대 팀 소요시간·분산 최소화
- LLM: 현재 제출 데모의 점수·경로·배분 산식에 사용하지 않음

## 9. 신뢰성·반증 가능성 / Reliability and falsifiability

- 모든 결과에 실행모드, 시각, 소스, 품질상태, 한계를 남긴다.
- 결측은 점수 구간을 넓히거나 `hold`로 바꾼다.
- 품질보고서가 `fail`이면 업무 생성·최적화를 중단한다.
- 경로가 없으면 직선거리로 대체하지 않고 `unavailable`을 반환한다.
- 최적화 후 중복·필수·고정·장비·근무시간을 다시 검사한다.
- `manual_approval_required=true`를 고정해 자동 현장 지시를 차단한다.

## 11. 제출 전 남은 게이트 / Remaining gates

1. 제주데이터허브 ID 1027 상세 페이지에 별도 라이선스가 표시되지 않아, 최종 ZIP에 원본을 넣기 전 이용조건을 확인해야 한다.
2. 항공·여객선 4종은 실응답을 확보할 때까지 점수·지도에 반영하지 않는다.
3. F2에서 ITS 시간·일간 통계와 시점고정 재생으로 1·3·6시간 시나리오를 평가해야 한다.
4. 캐시 데모의 파생 데이터 재배포 조건도 S4 제출 ZIP 전에 최종 검토해야 한다.
