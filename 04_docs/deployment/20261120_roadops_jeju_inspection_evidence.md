# 제주데이터허브 점검 근거 기능 / Jeju inspection evidence

2026-11-20. 실제 공개 자료를 연결한 추가 기능이다. 학습형 사고 예측 모델 또는 자동 통제 기능이 아니다.

급경사지와 재해지구 합계 58행 중 해제 44, 정비 완료 3, 그 외 위치·현장 확인 11행이다. 사업 완료와 지정 해제는 다르다. 광령리는 비고에 2023-05-10 해제가 명시되어 자동 제안에서 제외한다. 실제 좌표·경계가 없어 행정지역 일치만 확인하며 도로의 직접 위험, 통제 또는 추가 점수로 바꾸지 않는다. 서귀포시 자료로 일반화하지 않는다. 행정동/법정동 불일치로 누락될 수 있다.

젖음/습기 2005–2020년: 사고 7,218건, 사망자 226명, 100×226/7,218 = 3.13명/100건. 통행량·노면 노출량이 없으므로 사고 발생확률이나 도로별 위험률로 해석하지 않는다. 예상 노면은 거점 날씨로 자동 선택하며 담당자가 수정할 수 있다. 도로 노면의 직접 관측값은 아니다. 빈칸을 0으로 바꾸지 않는다.

노면에 따른 물고임·배수·결빙·제설·해빙 확인 항목과 같은 행정지역의 미해제 지구 확인 항목을 생성한다. 사용자가 `점검계획에 반영`을 누르면 도로별 작업, 추천 순찰코스 및 브라우저 확인 기록에 출처와 기간을 포함한다. 추가 점검 시간이 필요한 경우 담당자가 작업 시간을 조정한다. 서버 영구 저장과 전자결재는 후속 범위이다.

## 거점 날씨 기반 예상 노면

- [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)의 초단기실황·초단기예보·단기예보를 사용한다. 교래 격자 (56,37), 용담 (52,38), 노형 (52,37)을 각각 수집한다. `depot_weather` 쿼리는 거점 좌표와 같은 격자·같은 예측 시점만 연결하며 다른 거점이나 제주 전역 요약으로 대체하지 않는다.
- 현재는 유효한 관측값을 우선하며 관측이 없거나 오래됐을 때 일치하는 예보를 사용한다. 1·3·6시간 후는 해당 시점 예보를 사용한다. 기온·강수형태·강수량·습도는 동일 출처에서 함께 가져온다. 화면에 관측/예보, 거점, 격자, 기준시각을 표시한다.
- 자동 규칙 `depot-weather-v1`: 비·소나기·빗방울 또는 양의 강수량 → 젖음/습기, 이때 기온 0℃ 이하 → 서리/결빙. 눈·눈날림 → 적설. 혼합 강수는 0℃ 이하에서 적설, 초과 시 젖음/습기. 무강수여도 0℃ 이하이고 습도 90% 이상이면 서리/결빙. 그 외 명시적 무강수 자료가 있으면 건조 추정. 해빙·기타는 직접 선택한다. 이는 점검 준비용 운영 규칙으로, 노면 온도·잔류 수분·적설 깊이 또는 검증된 결빙 예측 모델을 대신하지 않는다.
- 누락·유효하지 않은 값·수집 후 180분 초과 자료는 미확인으로 둔다. 현재 관측은 120분 이내, 예보는 목표 시점과 ±60분 이내여야 한다. 오래된 관측이 화면에서 만료되면 다음 데이터 갱신 또는 담당자 확인이 필요하다.
- `예상 노면`을 바꾸면 **담당자 수정**으로 표시한다. 거점·도로·예측 시점별 수정값은 현재 브라우저 탭의 세션에 저장되어 새로고침과 날씨 갱신 후에도 유지된다. 다른 조건으로 이동했다가 돌아와도 수정값을 복원한다. `자동 추천으로 되돌리기`로 최신 추천을 다시 적용한다.
- `점검계획에 반영`을 누를 때 자동/수동 구분, 규칙 버전, 현재 기상 근거, 수정 당시 근거와 시각을 계획·확인 기록에 보존한다. 날씨나 선택값 변경만으로 이미 반영한 계획을 덮어쓰지 않는다. 기존 기록과 다르면 다시 반영 안내를 표시한다. 점수·통제 여부는 자동 변경하지 않는다.

기상 자료 갱신: `python3 07_scripts/20261112_roadops_build_weather_timeline_v0_1.py` (기존 `DATA_GO_KR_SERVICE_KEY` 필요) → 기존 map snapshot 빌더 → Data 앱 build. 수집기는 기존 C-ITS 격자에 세 거점 격자를 합쳐 수집한다. 기상청 출처표시를 유지하고 API 키는 결과물에 포함하지 않는다.

## 출처·조건

- 노면 통계 원천 TAAS, 허브 공개 첨부 CSV 사용. 대응 공공데이터포털 [15095728](https://www.data.go.kr/data/15095728/openapi.do)은 무료·이용허락범위 제한 없음.
- 재해 최신 원본: [15056032](https://www.data.go.kr/data/15056032/fileData.do), 급경사지 [15056033](https://www.data.go.kr/data/15056033/fileData.do). 양쪽 무료·이용허락범위 제한 없음(2026-11-20 확인).
- 허브 863은 공개 미리보기 CSV 범위이다. API 총량 42개 또는 페이지에 적힌 2023년까지를 전부 사용했다고 표기하지 않는다. 전체 API를 추가 수집하려면 프로젝트 인증키와 응답 연도 필드를 별도로 검증한다.
- 기존 허브 1027 및 863의 원본 재배포 조건은 최종 ZIP에 포함하기 전에 개별 확인한다. 사용 여부와 원본 재배포 허락은 구분한다. 현재 기획서는 파생 집계와 실제 UI 캡처, 출처를 제시한다.
- 정규화 JSON에는 원본 SHA-256, 수집일, 기준일, 원천 URL이 들어 있다. 인증키는 포함하지 않는다.

## 재현

정규화 입력 `demo/jeju_inspection_evidence_v0_1.json`은 Git에 포함된다. 원본 CSV를 갱신할 때는 다음 이름으로 준비한 후 실행한다: `surface.csv`, `hotspots_hub.csv`, `steep_slopes.csv`, `natural_hazards.csv`.

```sh
python3 07_scripts/20261120_roadops_prepare_jeju_inspection_evidence.py --input-dir /path/to/official-csv --retrieved-at 2026-11-20
python3 07_scripts/20261113_roadops_build_map_snapshot_v0_1.py --build-status complete
```

그 뒤 대시보드 AGENTS.md에 명시된 Data 플러그인 build를 실행한다. 운영 자동 갱신에도 supplemental JSON을 매번 읽으므로 새 기능의 데이터가 사라지지 않는다. 원시 사고다발·노면·재해 레코드는 점수 입력에 임의 가산하지 않는다. 기존 TAAS 최근 자료 기반 점수와 허브 과거 이력 표시를 구분한다.

## 15장 기획서 구성

기존 PPTX의 초록 강조선, 도로선 배경, 프리텐다드 글꼴과 실제 운영 화면을 재사용한다. 표지와 마지막 장을 포함해 총 15장이다. Canva 온라인 원본을 직접 변경하지 않고 가져오기 가능한 편집형 PPTX를 별도로 생성한다.

| 제출 필수 항목 | 반영 슬라이드 |
| --- | --- |
| 분석 주제·구현 목표·사용자 문제 | 1–2 |
| 데이터 개요·핵심 기능·편의성·활용 방안 | 3–5, 8–12 |
| 필수 데이터명·출처·항목·수집·전처리·이용조건 | 3, 5–6 |
| Agent 역할·Workflow·Tool/API·판단과 자율 범위 | 7, 14 |
| 사용 모델과 후속 모델 연동 계획 | 7, 14 |
| 실제 실행 결과·검증 방법·한계 | 4–5, 10–13 |
| 개발 범위·기술 환경·UI·센터 사양·외부 의존성 | 7–12, 14 |
| 참여자·센터 활용·제출 패키지 계획 | 1, 14–15 |

현재 실행은 규칙·통계·방향성 최단경로·제약 계산이다. LLM은 미연동이며, 7장에 GPT-5.4 mini API를 후속 검토 모델로 명시했다. 계획 범위는 요청 구조화와 검증된 도구 결과 설명이며, 실제 구현 완료로 표기하지 않는다. API 키·사용료·네트워크 및 장애 시 기존 입력 화면 사용도 14장에 포함했다. 모델의 구조화 출력·함수 호출 지원은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에서 확인했다.

10–12장은 기존 2026-11-19 17:40 자료 기반 통제 시연을 유지한다. 완료 39.8분과 남은 60.8분을 합쳐 총 100.6분이며 소길리 포함 방문 3곳을 유지한다. 신규 경로 시간은 제한속도 기반 추정이고 최초 계획과 산정 기준이 달라 절감 실적으로 해석하지 않는다. 4장의 2026-11-20 점검 항목 반영 화면은 별도 기능 확인 사례다.
