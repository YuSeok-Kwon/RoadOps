## 1. 평가 전략 / Evaluation strategy

최종 평가는 내부 전문가 평가 70%와 ELO 기반 참가팀 상호 평가 30%를 합산한다. 전문가 평가의 원점수를 전체 점수 기준으로 환산하면 다음과 같다.

| 평가 영역 | 전문가 원점수 | 최종점수 실질 비중 | RoadOps 대응 전략 |
| --- | ---: | ---: | --- |
| 분석 주제의 타당성과 창의성 | 15 | 10.5% | 위험지도에서 끝나지 않고 제한된 공공 자원을 배분하고 재계획하는 Agent로 차별화 |
| 필수 데이터 활용 적절성 | 20 | 14.0% | 제주빅데이터센터 또는 제주데이터허브 실제 데이터 1종 이상을 핵심 계산에 사용하고 전처리·영향을 증명 |
| AI Agent 기술성 및 완성도 | 25 | 17.5% | 요청 해석→데이터 점검→위험 계산→최적화→검증→설명의 도구 실행 흐름을 안정적으로 완주 |
| 편의성 및 실용성 | 25 | 17.5% | 비전문 공무원이 자원 조건을 입력하고 지도·대안·변경 이유를 확인한 뒤 승인 가능 |
| 결과 신뢰성 및 재현성 | 15 | 10.5% | 출처·시각·결측·한계를 표시하고 테스트·캐시·매뉴얼로 동일 결과 재현 |
| ELO 참가팀 상호 평가 | - | 30.0% | 기획서만 보고도 문제, 차별점, 동작 화면, 정량 효과를 빠르게 이해하도록 구성 |
| 합계 | 100 | 100.0% | 기술성과 실용성을 먼저 완성하고 데이터 활용과 신뢰성으로 방어 |

동점 우선순위가 `AI Agent 기술성 및 완성도 → 편의성 및 실용성 → 필수 데이터 활용 적절성`이므로 이 세 영역을 구현 우선순위의 기준으로 삼는다.

## 4. 기능 우선순위 / Feature priorities

### P0 — 제출 전에 반드시 작동

- 실제 필수 제주 데이터 1종 이상의 핵심 계산 활용
- 위험점수와 데이터 신뢰도·결측 상태 분리
- 기상 실황과 예보의 구분, 기준·유효·수집시각 표시
- 항공·여객선 공식 API의 실응답·최신성 검증과 실제 집계/추정치 구분
- 제약조건을 위반하지 않는 자원 배분
- 자연어 요청에서 Tool을 호출해 결과를 완주하는 Agent
- 제주 도로 지도 기반 웹사이트, 배치 근거, 미배정 이유, 사용자 승인
- 폭우 또는 통제 1건에 대한 부분 재계획과 변경 설명
- 기준선 비교, 장애 안전성, 한 명령 실행, 캐시 데모

### P1 — ELO와 차별화에 효과가 큰 기능

- 안전 우선·이동시간 우선·업무량 균형의 복수 대안
- 팀 감소·폭우·통제 What-if 2개
- 위험지도, 팀 위치, 이동경로, 배치 전후 지표의 한 화면 비교
- 0·1·3·6시간 위험예측과 공항·항만 유입압력 시간 슬라이더
- 공항·항만 도착 증가가 주변 도로와 배치안에 미친 영향 설명
- “이 팀을 다른 곳에 보내면 무엇을 잃는가” 반사실 설명

### P2 — 제출 후 또는 시간이 남을 때

- 12~72시간 중기 위험예측과 선제 교대·장비 배치
- 숙박예약·렌터카·주차·관광지 혼잡 등 민간 또는 추가 승인 데이터 반영
- 팀 역량·특수장비·교대시간의 세밀한 모델
- 모바일 현장 보고, 사진 분석, 추천 피드백 학습
- 기관 간 공동 대응과 장기 예산 시뮬레이션

P2는 기획서의 발전 방향으로만 제시하고 P0 안정성을 희생해 구현하지 않는다.

## 4-1. 실시간·예측 데이터 설계 / Real-time and predictive data design

현재 파이프라인의 기상 값은 기상청 `getUltraSrtFcst`를 실행 시 조회한 **초단기예보**다. 최근 실행은 17시 발표분을 17:59에 수집해 18시 예보를 사용했다. 최신 예보에 가깝지만 관측 실황이 아니며, 상시 스케줄러도 아직 없다. 다음 구조로 실시간과 미래를 분리한다.

| 축 | 공식 후보 데이터 | 현재 위험에서의 역할 | 1·3·6시간 예측에서의 역할 | 해석 안전장치 |
| --- | --- | --- | --- | --- |
| 기상 실황 | 기상청 초단기실황, C-ITS 노면기상 | 현재 강수·풍속·기온·노면 상태 | 예측 기준시점 초기값 | 관측시각이 없는 C-ITS는 `degraded` 유지 |
| 기상 예보 | 기상청 초단기·단기예보, 기상특보 | 곧 도달할 위험의 선행 경고 | 강수·강풍·기온·특보의 시점별 피처 | `base_at`과 `valid_at`을 분리하고 예보버전 보존 |
| 항공 유입 | 한국공항공사 실시간 운항정보, 제주공항 시간대별 도착 승객 | 지연·결항·도착 집중에 따른 공항 주변 노출 | 예정·변경 도착시각과 집계 승객으로 유입량 전망 | 실제 승객 수가 없으면 편수·기종·정원은 명시적 추정치로만 사용 |
| 여객선 유입 | KOMSA 운항일정·출항통제·정원, 일·월별 운송인원 | 제주항·연안항 주변 유입과 통제·결항 압력 | 예정 입항과 기상·통제에 따른 도착 시나리오 | 정원은 탑승객 수가 아니며 실제 집계와 분리 |
| 교통 | 제주 ITS 실시간 속도, 1시간·일간 통계 | 현재 정체와 속도 급락 | 최근 추세와 같은 요일·시간대 기준선 | 0값·결측·센서 장애를 혼잡으로 오인하지 않음 |
| 달력·행사 | 공휴일, 제주 행사·축제 일정 | 현재 특수수요 플래그 | 예정 수요의 보조 피처 | 규모 근거가 없으면 가중치가 아닌 플래그로 사용 |
| 진행 중 이벤트 | C-ITS 위험·통제·작업 | 현재 위험과 접근 제약 | 해제시각이 없으면 지속·해제 두 시나리오 | 오래된 이벤트 자동 보류, 임의 종료시각 금지 |

항공·여객선 정보는 사고위험 자체가 아니라 **유입 노출과 운영 부담**이다. 따라서 v0.1 위험점수에 곧바로 가산하지 않고 `gateway_inflow_pressure`를 별도로 계산한다. 최종 `operational_priority`에서만 영향권 거리, 도착 후 15·30·60·90분 시차, ITS 혼잡 변화와 함께 제한적으로 반영한다. 개인 이동정보는 수집하지 않고 공항·항만·시간대 단위 집계만 사용한다.

예측 결과 역시 사고 발생확률로 표현하지 않는다. 각 도로 링크에 대해 `현재 위험`, `예측 우선순위`, `하한·상한`, `근거 커버리지`, `예측 유효시각`을 제공하고, 과거 표본이 부족하면 모델값 대신 지속성 기준선과 보수·기준·악화 시나리오를 보여준다.

공식 후보 API와 신청 페이지는 다음과 같다. 공공데이터포털 통합 서비스키가 있더라도 API별 활용신청과 개발계정 승인이 필요할 수 있으므로 G1에서 실제 권한과 응답을 각각 확인한다.

- 기상청 단기예보 조회서비스(초단기실황·초단기·단기예보): https://www.data.go.kr/data/15084084/openapi.do
- 기상청 특보 조회서비스: https://www.data.go.kr/data/15139476/openapi.do
- 한국공항공사 실시간 항공기 운항정보: https://www.data.go.kr/data/15163384/openapi.do
- 한국공항공사 전국공항 시간대별 탑승승객 수: https://www.data.go.kr/data/15167062/openapi.do
- 한국해양교통안전공단 운항 스케줄 정보: https://www.data.go.kr/data/15142302/openapi.do
- 한국해양교통안전공단 월별 출발기항지 운항통계: https://www.data.go.kr/data/15142310/openapi.do

## 4-2. 지도·웹사이트 설계 / Map and website design

제출용 MVP는 한 명령으로 실행되는 웹앱으로 만들고, 제주 기준 도로망 GeoJSON을 로컬에서 읽어 외부 지도 서비스 장애 시에도 핵심 레이어가 보이게 한다.

- 현재 위험: 도로 링크 색상, 위험등급, 점수 상·하한, 데이터 품질상태
- 미래 위험: 0·1·3·6시간 슬라이더와 시점별 변화 애니메이션
- 관문 유입: 제주공항·항만 도착 규모와 영향권을 원형·열지도 레이어로 표시
- 현장 상황: C-ITS 위험·통제·작업, 기상특보, 노면기상 아이콘
- 자원 배분: 팀 출발지, 방문 순서, 이동경로, 미배정 고위험 구간
- 설명 패널: 링크를 클릭하면 구성점수, 원천, 갱신시각, 결측, 배정·미배정 이유 표시
- 운영 흐름: 자원 입력 → 현재/예측 선택 → 대안 비교 → 담당자 수정·고정 → 승인
- 재현성: 실제 API 모드와 저장된 스냅샷 기반 캐시 데모 모드를 동일 UI에서 지원

## 7. 평가별 증거 체크리스트 / Evidence checklist

### 분석 주제의 타당성과 창의성

- 공무원의 구체적 업무와 의사결정 단위를 한 문장으로 정의
- 일반 LLM, 위험지도, 단순 우선순위와의 차이를 표로 비교
- 재계획과 What-if의 실제 전후 화면 포함

### 필수 데이터 활용 적절성

- 공식 데이터명, 출처 URL, 이용조건, 확보일, 기간, 행 수
- 사용 필드와 전처리 코드, 품질검사 결과
- 필수 데이터가 최종 위험도 또는 배분에 미친 영향·제거 비교

### AI Agent 기술성 및 완성도

- Tool 목록, 입력·출력 스키마, 실패 상태, 실행 로그
- LLM과 결정적 계산의 역할 분리
- 대표 요청과 재계획을 끝까지 수행한 테스트

### 편의성 및 실용성

- 자원 조건을 업무 용어로 입력
- 제주 도로 지도와 팀별 경로, 현재·예측 전환, 예상시간, 대안, 미배정 이유
- 담당자 수정·고정·승인 흐름과 센터 실행환경 적합성

### 결과 신뢰성 및 재현성

- 출처, 기준시각, 신선도, 결측, 한계, 품질상태
- 자동화 테스트, 기준선, 장애 시나리오, 재현 명령
- 실제 비밀키를 제외한 `.env.example`, 의존성 고정, 캐시 데모

## 8. 제출 중단 조건 / No-submit gates

다음 중 하나라도 해결되지 않으면 기능 추가를 중단하고 해당 항목부터 복구한다.

1. 제주빅데이터센터 또는 제주데이터허브 실제 데이터가 핵심 분석에 사용되지 않음
2. 대표 자연어 요청이 데이터 확인부터 배치 설명까지 완주하지 못함
3. 배치안에 중복 배정, 자원 초과, 금지 구간 같은 하드 제약 위반이 있음
4. API 실패 또는 결측을 정상값이나 저위험으로 표시함
5. 새 환경에서 README만으로 실행할 수 없음
