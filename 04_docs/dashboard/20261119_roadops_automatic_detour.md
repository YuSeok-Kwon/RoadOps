# RoadOps 통제 구간 자동 우회 계산

2026-11-19 구현 및 검증 기록.

> **2026-11-20 재검증 정정:** 아래 `4050430101` 사례는 통제 전후를 같은 도로망·비용으로 재계산하면 경로와 시간이 동일하다. 기존 저장 경로와 새 제한속도 경로를 비교한 결과이므로, 통제 때문에 우회가 발생했다는 증거로 사용하지 않는다. 발표 12·13장은 실제 경로가 바뀌는 `4050000302`(1100로) 사례로 교체했다. 같은 기준의 총 예상시간은 100.570 → 125.613분이며 120분보다 5.613분 초과한다. 상세 기준과 재현 절차는 [동일 기준 통제 전후 검증](20261120_roadops_same_basis_detour.md)을 참조한다. 아래 내용은 당시 구현 기록으로 보존한다.

## 사용 방법

1. 거점 선택 → AI 자동선택 → 출동 조건 확인 → 추천 경로 만들기.
2. 오른쪽 ‘통제 반영·대체 경로 계산’에서 통제 구간 번호를 입력한다. 여러 번호는 쉼표로 구분한다.
3. 첫 방문부터 어디까지 완료했는지 선택한다. 실제 사용한 시간을 알고 있으면 입력한다. 비워 두면 완료 구간의 기존 예상 이동·점검 시간을 사용한다.
4. ‘대체 경로 자동 계산’을 누른다. 지도에 통제 구간과 새 경로가 표시되며, 코스에는 완료 점검과 남은 방문이 함께 표시된다.
5. 현장 상황과 보류 사유를 확인하고 변경안을 확정한다. 계산만으로 실제 출동 명령을 보내지는 않는다.

표준노드링크의 번호는 방향이 있는 도로 구간을 뜻한다. 양방향 통제를 적용하려면 해당 방향들의 구간 번호를 모두 입력한다. 통제 정보의 자동 수집 기능은 이번 변경 범위에 포함되지 않는다.

## 소길리 확인 결과

발표 자료에서 사용한 **2026-11-19 17:40 고정 입력**을 재현했다. 최신 운영 데이터와는 별도 사례다.

- 용담 출동팀 2명, 가용 120분, 최대 3곳.
- 광령리 평화로 점검 완료. 기존 사용 시간 39.793분 유지.
- 통제 가정: 링크 `4050430101`.
- 예래동 1100로 필수 점검 유지.

| 방문 | 상태 | 해당 이동 | 점검 | 누적 시간 |
|---|---|---:|---:|---:|
| 광령리 평화로 | 완료 기록 유지 | 기존 24.793분 | 기존 15분 | 39.793분 |
| 소길리 평화로 | 통제 구간을 피하는 경로 확보 | 5.802분 | 15분 | 60.595분 |
| 예래동 1100로 | 필수 점검 유지 | 24.968분 | 15분 | 100.563분 |

**3곳 모두 포함, 보류 0곳.** 남은 이동·점검 60.770분, 총 100.563분, 여유 19.437분이다. 남은 두 이동 구간의 모든 링크를 검사해 통제 링크가 포함되지 않음을 확인했다. 기존 저장 경로의 소길리 이동에는 해당 통제 링크가 포함돼 있었다.

시간이 기존 101.2분보다 작아진 것은 효율 개선 실적이 아니다. 완료한 첫 구간은 기존 자료의 시간을 보존했으며, 새로 계산한 구간은 제한속도 기반 추정이다. 실제 교통 혼잡과 회전 제한은 새 경로 계산에 반영하지 않았다. 이 결과는 가정한 통제와 보유 도로망에서의 연결 가능성 검증이며 실제 현장 통행 확인을 대신하지 않는다.

## 계산과 범위

- 2026-10-14 국토교통부 표준노드링크 제주 도로망: 노드 27,656개, 방향 링크 37,087개.
- 통제 링크를 제외한 방향 그래프에서 Dijkstra로 새 경로를 탐색한다. 저장된 후보 경로만 거르는 방식에서 확장했다.
- 완료 방문의 마지막 지점부터 남은 방문 간 이동시간 행렬을 새로 만든다. 점검 지점의 링크 진입·이탈 시간을 포함한다.
- 기존 웹 배분기로 필수 점검, 팀 고정, 인원·차량 정원, 장비·기술·관할, 남은 시간과 최대 점검 수를 반영한다.
- 현재 선택팀의 기존 계획에 포함된 미완료 방문을 재검토한다. 다른 팀의 계획 변경, 신규 후보 추가, 실시간 GPS 현재 위치부터의 재탐색은 포함하지 않는다.
- 거점에서 출발하는 경우 기존 Python 규칙처럼 근접 도로망에 연결한다. 거점 연결 시간은 20km/h 추정이며 실제 진입로의 별도 검증은 없다.
- 비용은 제한속도(10–110km/h 범위) 또는 누락 시 30km/h 기준이다. 신호, 회전 제한, 실제 정체, 현장 통행 제한의 자동 반영은 포함하지 않는다.
- 새 이동시간과 방문 순서는 제안이다. 담당자 검토 후 확정한다. 확정은 기존 웹 세션의 동작이며 서버 승인 저장이나 외부 출동 시스템 연계는 포함하지 않는다.

Web Worker에서 계산해 화면 응답을 유지한다. 입력 변경 시 이전 결과와 확정 버튼을 무효화하고, 오래된 작업 응답은 무시한다. 알 수 없는 링크, 경로 단절, 필수 점검 불가능 시 원래 경로를 대신 표시하지 않고 사유를 제시한다. Worker는 화면 이탈 시 종료하고 30초 이상 지연되면 중단한다.

## 재현 및 검증

저장소 루트에서 실행한다. `node`는 설치된 Codex Node 실행 파일을 사용했다.

```sh
node --test 08_dashboard/roadops_map_v0_1/tests/*.test.mjs
.venv/bin/python -m pytest tests/test_travel_time.py tests/test_replanning.py -q
.venv/bin/python 07_scripts/20261119_roadops_check_sogil_detour.py
```

- 웹 테스트 33개 통과. 새 회귀 테스트 9개에는 소길리 경로·시간의 Python 결과 일치, 완료 기록 보존, 통제 링크 배제, 목적지 자체 통제, 필수 점검 실패, 실제 경과 시간 반영, 팀 고정, 잘못된 입력, 방향 그래프 경로 단절을 포함한다.
- Python 경로·부분 재계획 테스트 14개 통과.
- 별도 Python 검증 스크립트에서도 소길리·예래동의 링크 목록과 구간 시간, 총 100.563분이 일치했다.
- 설치된 Data 사전 빌드 런타임으로 빌드 성공. 보호된 셸·빌드 파일 변경 없음.
- Chrome에서 실제 버튼 → Worker 계산 → 지도 경로 3개와 통제 구간 1개 표시를 확인했다. 잘못된 링크와 119분 사용 조건의 실패, 입력 변경 시 확정 차단, 계산 중 입력 변경의 오래된 응답 무시, 입력 초기화도 확인했다.
- 17:40 사례 브라우저 재현은 검증 세션에서만 당시 스냅샷 응답을 제공했다. 운영 `src/data.json`을 과거 값으로 덮어쓰지 않았다.
- 밝은 화면·어두운 화면 및 폭 900px에서 입력 접근과 가로 넘침 없음을 확인했다. 브라우저 실행 오류 없음.
