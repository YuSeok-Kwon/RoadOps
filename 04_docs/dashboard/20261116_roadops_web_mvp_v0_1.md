# RoadOps 운영 웹 MVP v0.1 / Operations Web MVP v0.1

## 목표

MAP1 지도에서 확인하던 위험·팀 경로·재계획 결과를 담당자가 실제로 검토하고 승인하는 한 화면 흐름으로 연결했다.

운영 순서는 다음과 같다.

1. 팀·차량·인원·근무시간 확인
2. 현장 업무별 담당팀·고정·제외 조건 확인
3. 선택한 계획과 자원·업무 입력의 제약조건 재검증
4. 데이터 신선도, 이동시간 의미, 현장 재확인 안전장치 확인
5. 담당자 이름과 승인 사유 입력
6. 계획 지문을 포함한 승인 기록과 감사 로그 생성

## 구현 범위

- 안전 우선과 균형 운영의 검증된 두 배분안 선택
- 차량 가용 상태, 인원, 근무시간 입력
- 업무 담당팀, 고정, 제외 조건 입력
- 필수 업무 제외, 차량 정원, 팀 업무 수, 비가용팀 배정 검사
- 검증 계획과 다른 자원·담당팀·제외 변경 시 승인 차단
- 저장 스냅샷, 자유흐름 이동시간, What-if 시나리오 경고
- 세 가지 현장 확인과 담당자·사유가 모두 있을 때만 승인
- 자원·업무·검증·승인 이벤트의 브라우저 로컬 감사 로그
- 계획 상태의 결정적 `workflowFingerprint` 생성
- 승인 뒤 입력이 바뀌면 기존 승인을 현재 계획과 분리
- 데스크톱과 모바일 화면 대응

## 안전장치

현재 웹앱은 브라우저 안에서 새로운 최적화 경로를 계산하지 않는다. 따라서 자원 수, 근무시간, 개별 담당팀 또는 제외 조건을 바꾸면 기존 경로를 그대로 승인하지 않는다.

변경된 업무의 기존 경로는 지도에서 숨기고 다음 오류를 표시한다.

```text
백엔드 재계획이 필요합니다.
```

현재 버전에서 승인 가능한 계획은 A3에서 제약검증을 통과한 `safety_first`와 `balanced_operations` 두 안이다. 계산하지 않은 경로를 승인 가능한 것처럼 표시하지 않는 것을 우선했다.

## 브라우저 검증

- 검증된 안전 우선 계획: 오류 0건, 주의 2건
- 안전확인 3개, 담당자, 승인 사유 입력 전 승인 버튼 비활성화
- 변경안 검증 후 승인 성공 및 계획 지문 기록
- 감사 로그에 안전확인 3건, 검증 1건, 승인 1건 기록
- 동부팀 인원 2명→1명 변경 시 `RESOURCE_REPLAN_REQUIRED`로 승인 차단
- 이전 승인 지문과 변경된 현재 계획 지문 분리
- 데스크톱 inspector 가로 넘침 0건
- 390×844 모바일 화면의 body/page/workflow 가로 넘침 0건

## 한계

- 승인·감사 로그는 현재 브라우저 `localStorage`에만 보존된다. 서버 영속 감사 로그가 아니다.
- 현재 승인 상태는 공모전 데모 흐름이며 실제 행정 전자결재나 현장 지시를 발생시키지 않는다.
- 수정된 자원·업무를 사용한 대화형 재최적화는 아직 Python 최적화 엔진과 웹 API로 연결되지 않았다.
- 위험 데이터는 저장 스냅샷이며 실시간 피드가 아니다.
- 이동시간은 자유흐름 추정치이며 실시간 ETA가 아니다.
