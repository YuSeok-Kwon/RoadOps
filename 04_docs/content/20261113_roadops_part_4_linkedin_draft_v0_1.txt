AI와 함께 제주 도로위험 순찰배치 Agent를 만들고 있습니다 — RoadOps 4부

계획을 한 번 만드는 Agent에서, 상황이 바뀌면 영향받은 부분만 다시 계획하고 이유까지 보여주는 Agent로 확장했습니다.

지난 작업에서는 제주 실제 도로망과 근무시간·장비·필수 업무를 반영해 안전 우선과 업무 균형 두 순찰계획을 만들었습니다. 이번에는 사용자의 한 문장을 7개 Tool로 연결하고, 도로통제·폭우 발생 시 부분 재계획한 결과를 제주 도로 지도에서 비교할 수 있게 했습니다.

[Agent 도구 흐름]

“팀 3개와 차량 3대로 2시간 안에 순찰계획을 만들어줘”라는 요청은 다음 단계를 거칩니다.

• 요청 해석
• 입력 데이터 품질검사
• 위험 이벤트의 링크 단위 작업 통합
• 108개 도로망 경로 확인
• 안전 우선·업무 균형 최적화
• 하드 제약 독립 재검증
• 결과와 한계 설명

각 Tool은 입력·출력·상태·제한사항을 JSONL 감사 로그에 남깁니다. 15,755개 실행 가능한 조합을 비교한 결과 두 대안 모두 9개 작업 배정, 위험가중 커버리지 100%, 제약 위반 0건을 유지했습니다.

[상황이 바뀌면 전체를 다시 섞지 않습니다]

도로통제 What-if에서는 기존 북부팀 경로가 통제 링크를 사용하고 있음을 확인했습니다. 북부팀의 남은 경로만 다시 계산하고 동부·서부팀, 완료 업무와 운영자 고정 업무는 그대로 유지했습니다.

• 영향팀: 북부팀 1개
• 이동시간 변화: +0.481분
• 위험 커버리지 변화: 0%p
• 제약 위반: 0건

폭우 What-if에서는 영향지역의 위험 우선순위, 점검시간과 이동시간을 보수적으로 조정했습니다. 북부·서부팀의 남은 업무만 다시 비교했고 동부팀 계획은 유지했습니다.

• 영향팀: 북부·서부팀 2개
• 이동시간 변화: +0.815분
• 위험 커버리지 변화: 0%p
• 제약 위반: 0건

[제주 도로 지도 시각화]

국토교통부 제주 표준링크 실제 좌표를 사용해 위험과 배분 결과를 한 화면에 올렸습니다.

• 현재·1·3·6시간 위험 링크 44개 행
• 안전 우선·균형 운영 팀 경로 비교
• 통제·폭우 영향 링크와 재계획 전후 경로
• 링크별 점수 상하한, 근거 충족률, 점수 구성요소, 품질 플래그
• 데이터 대상시각과 스냅샷 신선도

근거가 부족한 미래 링크는 0점으로 채우지 않고 ‘—’로 표시합니다. 아직 실응답을 확보하지 못한 공항·항만 유입압력도 임의 값을 넣지 않고 ‘데이터 미연결’로 남겼습니다.

[AI를 어떻게 활용했나]

AI는 어떤 팀을 보낼지 감으로 결정하지 않았습니다. Agent Tool의 책임과 중단 조건, 부분 재계획에서 보존할 상태, 지도에서 위험도와 신뢰도를 구분하는 방법을 함께 설계했습니다. 이후 Python 재계획 로직과 React 지도 화면을 구현하고, 통제·폭우·결측·반응형 실패 사례를 테스트로 고정했습니다.

위험점수, 도로망 경로, 최적화, 영향팀 판정과 제약 검증은 모두 결정적인 Python Tool이 계산합니다. 생성형 AI는 검증된 결과를 구조화하고 설명하는 협업 파트너로 사용했습니다.

현재 자동화 테스트는 140개가 통과했습니다.

다만 아직 실제 운영 서비스는 아닙니다. 현재 지도는 저장 스냅샷이고, 이동시간은 실시간 ETA가 아닌 자유흐름 추정치입니다. 통제와 폭우도 실제 발생 사실이 아닌 What-if이며 모든 배분 결과는 담당자 승인 전 현장 지시로 사용할 수 없습니다.

다음 단계는 담당자가 지도에서 업무를 고정·제외하고 변경안을 승인할 수 있는 웹 흐름과 실시간 갱신 파이프라인입니다.
