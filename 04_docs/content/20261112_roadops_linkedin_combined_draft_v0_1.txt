AI와 함께 제주 도로위험 순찰배치 Agent를 만들고 있습니다 — RoadOps 1부

이번에는 제주 AI·빅데이터 공모전을 준비하며, 공무원의 도로 순찰 자원 배분을 돕는 AI Agent ‘RoadOps’를 만들고 있습니다.

“오늘 순찰차 4대를 어느 도로에 먼저 보내야 할까?”

처음에는 위험한 도로를 지도에 표시하면 될 것 같았습니다. 하지만 실제 업무에서는 위험도만큼 이동시간, 가용 인력, 통제구간, 근무시간과 데이터 신뢰도가 중요합니다.

그래서 첫 작업은 AI 모델이 아니라 데이터 검증이었습니다. 국토교통부 전국표준 노드링크에서 제주 노드 27,656개와 링크 37,087개를 추출하고, 제주 C-ITS·ITS·기상청·TAAS 데이터를 같은 도로 기준으로 연결할 수 있는지 확인했습니다.

ITS 실시간 교통정보 12,081건 중 11,906건은 기준망과 정확히 연결돼 98.55%를 기록했습니다. 반면 C-ITS 도로위험정보는 당시 33건 중 24건만 정확히 연결됐고, 노면기상 12건은 모두 link_id가 -1이었습니다. C-ITS에는 제공기관 발생시각도 없어 단일 호출만으로 정말 실시간인지 증명할 수 없었습니다.

API가 정상 응답한다는 것과 의사결정에 안전하게 쓸 수 있다는 것은 다른 문제였습니다.

[AI를 어떻게 활용했나]

AI와 함께 문제를 인증, 응답 구조, 건수, 최신성, 도로망 결합으로 나눴습니다. 실제 응답과 명세가 다른 부분을 찾아 파서를 수정하고, 오류 판별·키 마스킹·품질 게이트·자동화 테스트를 구현했습니다.

다만 최신 데이터 나이와 링크 결합률은 LLM이 판단하지 않습니다. Python 코드가 정해진 기준으로 계산하고, 확인할 수 없는 값은 추측하지 않고 보류합니다.

[현재까지 구현한 범위]

• 제주 기준 도로망 37,087개 링크 구축
• C-ITS 4개·ITS 3개 운영 API 검증
• ITS 링크 정확 결합률 98.55% 측정
• C-ITS 연속 스냅샷과 변경·소멸 추적
• 정확 ID 결합·좌표 보조 결합·자동 배제 분리
• API 키와 오류 응답의 비밀값 마스킹

[최종 목표]

RoadOps의 목표는 위험지도를 만드는 것이 아닙니다. 공무원이 인력·차량·근무시간을 입력하면 Agent가 데이터 상태부터 검사하고, 제약을 지키는 여러 순찰안을 근거와 함께 제시하는 것입니다.

다음 기록에서는 결측을 0점으로 만들지 않고, 근거가 부족하면 점수 자체를 보류하는 ‘설명 가능한 위험점수 v0.1’을 다뤄보겠습니다.
