# AI와 함께 제주 도로위험 순찰배치 Agent를 만들고 있습니다 — RoadOps 두 번째 기록

“지금 들어온 도로위험 정보, 정말 지금 상황일까?”

API가 정상 응답하고 데이터가 여러 건 들어왔다고 해서 바로 실시간 의사결정에 사용할 수 있는 것은 아닙니다. 인증에 성공했는지, 응답을 제대로 읽었는지, 데이터 시각이 최신인지, 같은 도로를 가리키는지까지 서로 다른 질문이기 때문입니다.

지난 기록에서는 국토교통부 전국표준 노드링크에서 제주 노드 27,656개와 링크 37,087개를 추출해 기준 도로망을 만들었습니다. 이번에는 실제 제주 C-ITS 4개 API와 ITS 3개 API를 연결해 인증, 응답 구조, 레코드 수, 실시간성, 도로망 결합률을 차례로 검사했습니다.

두 인증키는 모두 유효했고 7개 호출의 실패는 0건이었습니다. ITS 실시간 교통정보는 12,081건을 반환했습니다. 최신 데이터 시각은 검사 시점보다 1.498분 전으로, 설정한 30분 신선도 기준을 통과했습니다. 1시간 통계와 일간 통계도 각각 12,081건 모두 요청한 기준시각과 일치했습니다.

처음 예상과 다른 문제도 바로 발견됐습니다. 초기 파서는 대문자 `Info`를 예상했지만 실제 운영 응답은 소문자 `info`를 사용했습니다. API는 정상이어도 코드가 데이터를 0건으로 읽을 수 있는 상태였습니다. 실제 응답 구조를 반영해 파서를 수정하고 이 사례를 자동화 테스트로 고정했습니다.

더 큰 문제는 도로망 결합이었습니다. ITS는 12,081건 중 11,906건이 제주 기준망과 정확히 연결돼 98.55%를 기록했습니다. 반면 C-ITS 도로위험정보는 33건 중 24건, 72.73%만 정확히 연결됐습니다. 도로작업 1건은 일치하지 않았고, 노면기상 12건은 모두 `link_id=-1`이었습니다.

C-ITS 응답에는 관측시각이나 갱신시각도 없습니다. 따라서 단일 호출만으로 지금 발생 중인 상황인지 오래된 레코드인지 증명할 수 없습니다. RoadOps는 이를 억지로 ‘실시간’으로 판정하지 않고 `확인 불가`로 남깁니다.

[AI를 어떻게 활용했나]

저는 AI를 데이터의 의미를 대신 판단하는 도구보다 기획자·개발자·리뷰어에 가까운 협업 파트너로 사용했습니다.

대화로 “키가 작동하는가”라는 질문을 인증·스키마·건수·시간·도로망 호환성으로 나눴습니다. 이후 실제 응답과 초기 가정의 차이를 찾고, 응답 추출기와 제공자 오류 판별, 인증키 마스킹, 감사 보고서와 테스트를 함께 구현했습니다.

반면 최신 데이터 나이와 링크 결합률은 Python 코드가 정해진 기준으로 계산합니다. LLM이 데이터가 충분히 최신하다고 추측하거나, 일치하지 않는 도로를 임의로 연결하지 않습니다.

[현재까지 구현한 범위]

• 제주 기준 도로망 노드 27,656개·링크 37,087개 구축

• C-ITS 4개·ITS 3개 실제 운영 API 인증 검사

• 제공 건수와 실제 추출 건수 일치 검사

• ITS 실시간 데이터 30분 신선도 게이트

• 시간·일간 통계 요청 기준시각 전량 일치 검사

• ITS 12,081건의 정확 링크 결합률 98.55% 측정

• C-ITS 미결합·시간정보 부재·노면기상 `link_id=-1` 탐지

• 인증키가 로그와 보고서에 남지 않는 안전장치

• 실행 가능한 감사 노트북과 자동화 테스트 45개

물론 아직 완성은 아닙니다. C-ITS의 실시간성을 확인하려면 일정 간격으로 스냅샷을 저장해 추가·변경·삭제를 추적해야 합니다. 노면기상과 미결합 이벤트는 위·경도로 도로 형상에 보조 결합하되, 정확 ID 결합과 근거 수준을 구분해야 합니다. ITS에서 일치하지 않은 175개 링크의 버전 차이도 확인해야 합니다.

또한 제주 API가 평문 HTTP만 제공한다는 보안 한계가 있습니다. 현재 호출은 명시적으로 허용한 검사에서만 수행하고 있으며, 운영 환경에서는 제공기관의 HTTPS 지원 확인과 제한된 키·키 순환 정책이 필요합니다.

[최종 목표]

RoadOps의 목표는 데이터가 들어왔다는 이유만으로 순찰차를 보내는 시스템이 아닙니다.

공무원이 가용 인력과 차량을 입력하면 Agent가 데이터의 인증 상태, 갱신시각, 도로망 결합 근거부터 검사하고, 확인 가능한 정보만으로 여러 순찰배치안을 제시하는 것이 목표입니다. 시간이 없거나 도로를 확정할 수 없는 이벤트는 숨기지 않고 보류 사유와 함께 보여주며, 최종 판단은 담당자가 내립니다.
